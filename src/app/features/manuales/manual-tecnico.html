1 Visión general y stack

Facturación Bee son dos repositorios independientes —no comparten workspace, ni despliegue, ni git— más un proyecto de Supabase compartido.

Pieza Tecnología Responsabilidad
Front-End Angular 21 · standalone · zoneless · signals · Tailwind v4 (solo el reset) Toda la lógica de negocio y la interfaz
Back-End NestJS 11 · Express 5 · Nodemailer 9 · Node ≥ 22 Solo el envío de correo con adjuntos. No toca Supabase
Datos Supabase · PostgreSQL 17 · Storage Persistencia y reglas de negocio en funciones SQL

Dependencias del front

  • @supabase/supabase-js — cliente de datos y Storage.
  • xlsx — lectura de los Excel. Solo lectura; para exportar se usa CSV propio.
  • jszip — descarga del periodo comprimido.

No hay librería de gráficos. El anillo, las barras y la serie del tablero son SVG propio: para tres formas, 150-400 kB de dependencia y su superficie de vulnerabilidades no compensan.

2 Estructura del proyecto

Carpeta Qué contiene

shared/ui/ Sistema de diseño: icon, badge, kpi-card, empty-state, modal, ciclo, direcciones, toc, gráficos

Alias: @core/*, @shared/*, @features/*, @env. Dentro de core/ se usan rutas relativas (../models); fuera, los alias.

3 Enrutamiento y sesión

Todas las rutas de módulo cuelgan de /app y usan loadComponent. Dos guards: authGuard en todo /app y adminGuard en Usuarios, Auditoría y los manuales técnicos.

El acceso a cada módulo del ciclo no lo controla un guard de router, sino la etapa del periodo: cada pantalla comprueba periodStore.alcanzo('etapa') y muestra un estado vacío explicativo si aún no le toca.

Limitación conocida de la sesión
La sesión vive en localStorage['bee.session'] como JSON sin firmar, y las contraseñas están en texto plano en la tabla usuarios. La bitácora tiene valor operativo, pero no es prueba forense hasta que exista autenticación real (Supabase Auth + hash).

4 Gestión de estado

La aplicación es zoneless (provideZonelessChangeDetection()): todo el estado va en signals. Un setTimeout que mute una propiedad normal no repinta nada.

  • Servicios de datos: señal privada _rows + asReadonly() público, loading y error (cadena vacía, nunca null).
  • Derivados: siempre computed(). Nunca duplicar estado que se puede derivar.
  • `effect()`: solo para reaccionar al cambio de periodo. Nunca para registrar auditoría ni para escribir señales.

La doble clave de periodo

Es la trampa número uno del proyecto:

Llamada Devuelve Se usa para
periodStore.period() '2026-08' Rutas de Storage, clave de periodos, claves de localStorage
periodStore.label() 'Agosto 2026' Todas las columnas periodo_* de la base de datos

Consultar una tabla con el id en vez de la etiqueta no da error: devuelve cero filas.

5 Base de datos

Proyecto Supabase xatapilakdhlmgfjvdco, PostgreSQL 17. Convención de columnas: <concepto>_<sufijo_de_tabla>.

Tabla Para qué Acceso
usuarios Cuentas y roles RLS activo sin políticas · solo RPC y la vista vw_usuarios
documentos_facturacion Índice de soportes subidos (URL de Storage) Directo
aprobacion_prefactura Las 25 columnas del Excel del cliente Directo
registro_facturacion_interna 13 columnas del Excel interno + 4 que añade Revisar Directo
facturas La factura como entidad: estado, envío, anulación y conciliación Solo RPC
periodos Catálogo de periodos y etapa del ciclo Solo RPC
parametros Retención, TRM, plazo, destinatarios, asunto, prefijo de factura Solo RPC · RLS sin políticas
auditoria Bitácora inmutable Solo RPC · revoke all incluido TRUNCATE

Advertencias estructurales

  • No hay ni una sola clave foránea. Todas las relaciones son por igualdad de texto.
  • En las tablas de detalle, montos, fechas y periodos son text. En facturas sí son numeric y date.
  • El join central del ciclo es id_colaborador_prefactura ↔ id_colaborados_facturacion_interna (sí, «colaborados»).
  • La columna entega_valor_prefactura va sin la «r», y existe año_prefactura con carácter no ASCII. No los «arregles» sin migrar los datos.
Deuda de seguridad abierta
Las tres tablas del ciclo tienen políticas RLS using (true) para anon, y la clave publicable viaja en el bundle: hoy la facturación es legible y escribible por cualquiera que tenga la clave. El bucket de Storage es público. Está pendiente de remediación.

La tabla respuestas_prospectiva pertenece a otro producto alojado en el mismo proyecto de Supabase. Es ruido para este aplicativo: no la toques.

6 Funciones RPC

Todas son SECURITY DEFINER con set search_path = public y grant execute a anon y authenticated. Las reglas de negocio que no pueden depender del navegador viven aquí.

Función Qué hace
fn_login Autentica y actualiza el último acceso. Sin coincidencia devuelve vacío
fn_touch_acceso Refresca el último acceso al actuar
fn_crear_usuario · fn_actualizar_usuario · fn_set_estado_usuario CRUD de cuentas. La contraseña vacía conserva la anterior
fn_listar_periodos · fn_crear_periodo Catálogo. La unicidad de (año, mes) la garantiza la base de datos
fn_avanzar_etapa Avanza el ciclo. Ignora los retrocesos: confirmar dos veces no deshace nada
fn_reabrir_etapa Retrocede, con motivo obligatorio
fn_orden_etapa Posición de una etapa. Es IMMUTABLE, no SECURITY DEFINER
fn_sincronizar_facturas Regenera las facturas desde el registro interno. Devuelve jsonb con creadas, omitidas y conflictos. Respeta anuladas y pagadas
fn_listar_facturas Facturas del periodo + días transcurridos y vencimiento calculados contra el plazo parametrizado. Orden natural por la parte numérica del secuencial
fn_marcar_enviada Deja constancia del envío. No pisa el estado anulada
fn_anular_factura Anula con motivo obligatorio. Rechaza anular una pagada
fn_registrar_pago Registra el pago y calcula retención y equivalente COP. Rechaza una anulada
fn_siguiente_secuencial Siguiente número libre sobre toda la historia, anuladas incluidas
fn_verificar_secuenciales Números del Excel que ya pertenecen a otro periodo, para avisar antes de guardar
fn_resumen_periodos Totales por periodo. La única consulta que cruza meses
fn_listar_parametros · fn_guardar_parametro Parámetros de negocio. guardar solo actualiza: no crea claves nuevas
fn_registrar_auditoria El único camino de escritura de la bitácora
fn_listar_auditoria · fn_resumen_auditoria · fn_filtros_auditoria Consulta paginada, métricas del filtro y valores para los desplegables

Por qué la lógica está en SQL y no en el navegador

  • La retención y el equivalente en COP los calcula fn_registrar_pago, y guarda la TRM concreta de la operación. Así todas las pantallas muestran la misma cifra.
  • Los días transcurridos y el vencimiento los calcula fn_listar_facturas contra el plazo parametrizado, por el mismo motivo.
  • La IP y el navegador de la auditoría los lee la base de datos de current_setting('request.headers'): no llegan como parámetro, así que el cliente no puede falsearlos.

7 Numeración de facturas

secuencial_factura es único en toda la tabla, no por periodo. La restricción se llama facturas_secuencial_global_unico.

Antes la unicidad era (periodo_factura, secuencial_factura), así que un BEE771 anulado en agosto podía reaparecer en septiembre sin que nada lo impidiera. Un número de factura identifica un documento contable: no es del mes, es de la empresa, y anular no lo libera.

Las cuatro barreras

  1. 1
    Carga consulta fn_verificar_secuenciales al interpretar el Excel y avisa antes de guardar nada.
  2. 2
    fn_sincronizar_facturas filtra los conflictivos antes del insert y los devuelve en su informe.
  3. 3
    La restricción de la base de datos lo impide aunque se intente por SQL directo.
  4. 4
    fn_siguiente_secuencial propone siempre un número libre, contando facturas y registro interno de todos los periodos.
Al tocar la sincronización
El on conflict apunta a (periodo, secuencial) y no cubre el índice global. Si se quita el filtro de conflictivos, un número repetido entre periodos aborta toda la sincronización con una violación de unicidad.

El prefijo (BEE) es el parámetro prefijo_secuencial, no un literal.

8 Storage de archivos

Bucket único facturacion-bee, público, 5 MB por archivo. Ruta: {{ '{periodId}/{slug-tipo}/{timestamp}-{nombre}' }}, por ejemplo 2026-08/factura-bee/1785449571300-FACTURA_BEE_671.pdf.

El timestamp evita colisiones entre archivos del mismo nombre. La URL pública resultante es la que se guarda en documentos_facturacion y la que el backend de correo descarga para adjuntar.

Sin transacciones
documentos.service.ts sube el archivo y después inserta la fila. Un fallo parcial deja archivos huérfanos en Storage o filas de detalle sin índice. Y guardarPedido no deduplica: subir dos veces el mismo PCC crea dos filas.

9 Excel y montos

Los Excel se parsean con xlsx por índice de columna (r[0]…r[24]) y siempre de la hoja 0. No se validan las cabeceras: si el cliente mueve una columna, los datos entran desplazados en silencio.

Montos: precisión al centavo

  • Al parsear se trunca a dos decimales sobre el texto, sin redondear.
  • Toda comparación se hace en centavos enteros (monto.util.ts), nunca con aritmética en coma flotante.
  • Es lo que evita que dos importes idénticos se declaren distintos por un error de representación de 0.1 + 0.2.
Dependencia con vulnerabilidades conocidas
xlsx@0.18.5 arrastra CVE conocidas y parsea archivos que llegan de fuera. SheetJS ya no publica en npm; la vía oficial es su CDN. Pendiente de actualizar.

10 Integración de correo

El front no envía correo: se lo pide al backend dev-back-facturacion-bee, que es un servicio de NestJS desplegado aparte y autenticado con x-api-key.

Endpoint Qué hace
GET /api/health Latido. Sin autenticación
GET /api/health/details Configuración efectiva del servicio
GET /api/email/verify Si el buzón puede enviar y por qué no. Autentica por SMTP sin enviar nada
POST /api/email/send El que usa el aplicativo. Responde 200, no 201

El diagnóstico del buzón

/api/email/verify responde 200 siempre, incluso con el buzón caído: la comprobación se hizo con éxito y su resultado es un diagnóstico (operativo, remitente, codigo, titulo, detalle, solucion, tecnico). Devolver 502 haría indistinguible «el buzón no puede enviar» de «no pude preguntar». Cachea 60 s para no acumular intentos de inicio de sesión contra Office 365.

La regla que no se debe invertir
Se bloquea el envío por un diagnóstico negativo, nunca por la ausencia de diagnóstico. Un backend desplegado sin el endpoint devuelve 404, y bloquear ahí dejaría el aplicativo inservible por una causa que ni siquiera se ha confirmado.

Los adjuntos van por URL

El front manda attachmentUrls con las URL públicas de Storage y el backend las descarga. Codificar en base64 haría crecer el cuerpo un 37 % y lo cortaría el analizador de cuerpo antes de llegar. El backend valida el host contra una lista blanca (*.supabase.co) y bloquea rangos privados: es la protección anti-SSRF.

Cada correo lleva hasta tres adjuntos: Factura BEE, Pedido de Compra y el Excel de Aprobación de Prefactura del periodo (RF-ENV-01).

Decisiones de diseño en Entregar

  • La composición vive fuera del componente, en core/utils/correo.util.ts, como función pura con sus pruebas.
  • Ediciones por sobrescritura: una señal de cambios encima del computed base, no una copia. Lo que no se toca sigue derivándose de los datos.
  • Mecanismo de epoch: un contador que se incrementa al cambiar de periodo, al detener el envío y al destruir el componente. El bucle lo comprueba justo después de cada await. Por eso auditoria.registrar() nunca se espera con await ahí dentro.
  • Un 200 con rejected cuenta como enviado: el correo salió hacia los aceptados; reintentarlo duplicaría la factura en el buzón del cliente.
Bloqueo operativo conocido
El tenant de Microsoft 365 responde 535 5.7.139 SmtpClientAuthentication is disabled for the Tenant. Mientras siga así, todo envío real falla. No es una contraseña mal escrita: se resuelve con Set-CASMailbox -SmtpClientAuthenticationDisabled $false y revisando los valores predeterminados de seguridad en Entra ID.

11 Sistema de diseño

Todo vive en src/styles.css. Tailwind está instalado pero no se usa como framework de utilidades: no hay ni una clase utilitaria en las plantillas. Aporta solo su reset. Antes de escribir una clase nueva, búscala allí.

Tokens

  • Color: carbón (--ink) + miel (--honey) + semánticos --ok, --info, --bad, --warn, cada uno con su -soft y -line.
  • Espaciado: --sp-1 … --sp-10.
  • Movimiento: --dur-1 … --dur-4 y --ease-out. No escribas duraciones literales.
  • Elevación: --shadow-xs … --shadow-xl, siempre en dos capas (contacto + ambiental).
  • Alto de la ventana: --app-h. Nunca uses 100vh ni 100dvh sueltos (ver abajo).

Componentes propios

Componente Para qué

bee-ciclo La línea del ciclo, en variante cinta (encabezado) o panel (tablero). Fuente única
bee-direcciones Campo de correos como etiquetas, con validación individual

El scroll: por qué está montado así

El documento no se desplaza nunca. El único panel que hace scroll es .main, y el shell mide exactamente --app-h con overflow: hidden.

Tres reglas que no se deben romper, cada una arregla un fallo real que se dio:

  • overscroll-behavior: contain en todo contenedor con scroll. Sin él, al llegar al final el scroll se encadena al documento.
  • .main es position: relative. Sin eso, un .sr-only —que es position: absolute— se coloca en coordenadas del documento y lo estira: era la causa de que la aplicación «se subiera y quedara en blanco» al llegar abajo del todo.
  • El desenfoque del encabezado va en .topbar::before, no en .topbar. backdrop-filter convierte al elemento en raíz de fondo y rompe el pintado de los descendientes que se salen de sus límites.

Adaptación a móvil

Puntos de corte en 1080 · 900 · 640 · 480. Las tablas de datos usan table.dt.dt-stack: por debajo de 640 px cada fila se convierte en una tarjeta, y el rótulo de cada celda sale de su data-label. Si añades una columna, añade también su data-label, o la tarjeta saldrá sin rótulo.

Trampas de CSS heredadas

  • .ti solo existe como .tile .ti y .fx como .doc-item .fx: fuera de ese ancestro se quedan a medio pintar, sin error ni aviso. Antes de reutilizar una clase global, comprueba si su regla tiene ancestro.
  • .slot-error y .slot-link solo existen en carga.css.

12 Entornos y despliegue

Configuración por entorno

La configuración pública —URL de Supabase, clave publicable, URL y clave del backend— está en src/environments/environment.ts y environment.production.ts, que sí se versionan. Angular sustituye uno por otro al compilar (fileReplacements).

El front no lee variables de entorno
En el navegador no existe process.env: todo lo que la aplicación necesita se compila dentro del JavaScript. No hace falta crear variables en Vercel para el front, y crearlas no tendría efecto. El .env de la raíz es residuo: sus 22 variables no las usa nadie.

Comandos

Comando Qué hace
pnpm install Instala dependencias
pnpm start Servidor de desarrollo en localhost:4200
pnpm build Compilación de producción
pnpm test Pruebas con Vitest
Desarrollo escribe en producción
environment.ts y environment.production.ts apuntan al mismo proyecto de Supabase. Trabajar con pnpm start modifica los datos reales. No hay entorno de pruebas separado.

13 Convenciones y pendientes

Convenciones de código

  • Angular: standalone sin standalone: true, OnPush, input()/output(), inject(), control de flujo nativo (@if/@for), bindings class/style.
  • Idioma: español para el dominio conectado a Supabase, para el SQL, para los comentarios y para todos los mensajes de interfaz; inglés para la API de framework. Si dudas: capa nueva → español.
  • Modelos: XxxInsert = payload sin PK; XxxRow extends XxxInsert = fila completa.
  • null vs undefined: null para lo que viaja a la base de datos; undefined para «no encontrado»; '' para las señales de error.
  • Visibilidad: private readonly para lo que la plantilla no usa, protected readonly para lo que sí.

Cómo registrar una acción en la bitácora

Una línea, en el componente —que es quien conoce la intención y el desenlace—, nunca en un servicio de datos. Quien llama dice solo qué pasó: el usuario, el rol y el periodo los añade el servicio; la fecha, la IP y el navegador, la base de datos.

  • Nunca dentro de un effect(): se ejecutan al montar y en cada cambio de periodo, así que generarían una fila cada vez que alguien abre la pantalla.
  • Nunca registres contraseñas, las URL públicas de Storage ni la clave del backend de correo.
  • Si necesitas una acción o un módulo nuevos, añádelos a las uniones de auditoria.model.ts: son tipos cerrados a propósito.
